## Resume Guidelines

### Format Basics

| Property | Recommendation |
|----------|----------------|
| Length | 1 page (2 pages for 10+ years of experience) |
| File format | PDF always (ATS-parseable) |
| Font size | 10–12pt body, 11pt ideal |
| Margins | 0.5–1 inch, consistent on all sides |
| Layout | Single column only |
| Font | Standard: Calibri, Arial, Helvetica, or Times |

---

### Section 1 — Header / Contact Info *(Required)*

The very top of your resume. Must be immediately scannable.

**What to include:**
- Full name — largest text on the page (16–20pt, bold)
- Professional email (e.g. `firstname.lastname@gmail.com`)
- Phone number
- City & Country (no full street address)
- LinkedIn URL (shortened: `linkedin.com/in/yourname`)
- GitHub URL
- Portfolio URL

**Rules:**
- No photo, no date of birth, no gender — irrelevant and risky in most regions
- Use a professional email address, not a nickname

---

### Section 2 — Professional Summary *(Recommended)*

2–3 sentences, tailored to each role. Tells the recruiter **who you are, what you do, and what you bring**. Never written in first person.

**✓ Good example:**
> Full-stack engineer with 5 years building distributed systems in Go and React. Led migration of monolith to microservices at Acme, reducing p99 latency by 40%. Seeking a backend-focused role at a product-led company.

**✗ Avoid:**
> Passionate, hardworking developer who loves to code and is eager to learn new technologies and contribute to a dynamic team environment.

---

### Section 3 — Technical Skills *(Required)*

Group skills into clear categories. Never use a single flat list.

| Category | Examples |
|----------|----------|
| Languages | Python, TypeScript, Go, Java, SQL |
| Frameworks | React, Node.js, FastAPI, Spring Boot |
| Cloud / Infra | AWS, GCP, Docker, Kubernetes, Terraform |
| Databases | PostgreSQL, Redis, MongoDB, DynamoDB |
| Tools | Git, GitHub Actions, Jira, Datadog |

**Rules:**
- Mirror keywords from the job description — ATS systems scan for these
- Only list what you can discuss fluently in an interview
- Do not rate skills with bars or stars — they're meaningless to reviewers

---

### Section 4 — Work Experience *(Required · Most Important)*

**Format per role:**
```
Job Title (bold)  |  Company Name  |  City, Country  |  Month YYYY – Month YYYY
```

Write **3–5 bullet points per role** using the **XYZ formula**:

> Accomplished **[X]** as measured by **[Y]**, by doing **[Z]**.

**✓ XYZ formula example:**
> Reduced API response time by 60ms (p95) by introducing Redis caching for user session data, eliminating 3M+ redundant DB reads per day.

**✗ Vague / task-based (avoid):**
> Worked on backend APIs and helped improve performance of the application.

**Rules:**
- Start every bullet with a strong past-tense verb (Built, Reduced, Led, Shipped, Automated, Migrated)
- Include metrics wherever possible: latency %, cost saved, users impacted, uptime %, team size
- List roles in reverse chronological order (most recent first)
- Prioritise impact bullets over task bullets — what changed because you were there?

---

### Section 5 — Projects *(Required for juniors, optional for seniors)*

List **2–4 projects**. Each entry should contain:
- **Project name** (with live link or GitHub URL)
- Tech stack used
- 2 bullets: what it does + what was technically interesting

**Rules:**
- Include a live link or GitHub repo for every project
- Focus on projects with real technical depth, not tutorial clones
- Mention scale: 10k daily users, 500ms ingestion pipeline, 95% test coverage
- For senior roles, trim or remove this section if space is tight

---

### Section 6 — Education *(Required)*

**Format:**
```
Degree, Field of Study  ·  University Name  ·  Graduation Year  ·  GPA (if ≥ 3.5 and recent grad)
```

**Rules:**
- Place at the **bottom** for 3+ years of experience; move to the **top** for new graduates
- Include relevant coursework only if very junior and space allows
- Bootcamps and online degrees: list the institution name and credential honestly

---

### Section 7 — Certifications & Awards *(Optional)*

One-liner per cert:
```
Certification Name  ·  Issuing Body  ·  Year
```

**Include:**
- Industry-recognised certifications: AWS, GCP, CKA, Azure, Kubernetes, etc.
- Only active / non-expired certifications
- Hackathon wins, open source contributions, and published papers

## Portfolio Guidelines

> **Your portfolio is a live product.** It should load fast, look professional on mobile, and let the work speak. The goal is to show *how* you think, not just what you built.

---

### Section 1 — Hero / Landing Section *(Required)*

The first thing visitors see. Must instantly answer: who are you, what do you do, how do I reach you.

- Name + professional title ("Full-Stack Engineer", not "Software Wizard")
- 1–2 sentence tagline — your specialisation and what you're looking for
- Clear CTAs: "View my work" and "Contact me" buttons above the fold
- Optional: clean, professional photo (skip selfies and heavy filters)

---

### Section 2 — Featured Projects *(Core — Required)*

The heart of your portfolio. Show **3–5 projects**. Quality over quantity — every project you add dilutes the best ones.

**Each project card should contain:**
- Title + one-line description of the problem it solves
- Tech stack badges (React, Node.js, PostgreSQL, etc.)
- Screenshot or demo GIF — the #1 thing most devs skip. Include it.
- Links: live demo + GitHub repo (both, not just one)
- One key highlight: a technical challenge solved or a metric achieved

**Each project's dedicated page should include:**
- **Problem statement** — why did you build this?
- **Architecture decisions** — why did you choose this stack?
- **Challenges and how you solved them** — this is what interviewers read most
- **What you'd do differently** — shows technical maturity

---

### Section 3 — About Me *(Required)*

2–4 paragraphs, written in first person (unlike the resume).

Cover:
- Your background and how you got into engineering
- Areas of specialisation ("I focus on performance-critical backend systems")
- What you're currently learning or exploring
- Something human — interests, side projects, motivations

**Avoid:** "passionate developer", "love solving problems" — show, don't tell.

---

### Section 4 — Skills / Tech Stack *(Required)*

Visual, grouped by category. Use icons (Devicon library) for recognition.

**Suggested groups:**
- Languages · Frontend · Backend · Cloud / DevOps · Databases · Testing · Tools

**Rules:**
- Do not use skill bars or percentage ratings — they're subjective and misleading
- Keep it scannable, not a wall of text

---

### Section 5 — Experience / Timeline *(Recommended)*

A timeline or card list of roles. Briefer than your resume:
- Company name + logo
- Role and dates
- 2–3 bullet highlights per role
- Link to company website

---

### Section 6 — Blog / Writing *(Optional — but powerful)*

Even 2–3 technical posts can differentiate you sharply. Link to Medium, Dev.to, or Hashnode.

**Topics that work:**
- Deep dives into a bug you fixed
- Architecture decisions you made
- A library or tool you built
- System design walkthroughs

---

### Section 7 — Open Source Contributions *(Optional)*

- Link to your GitHub profile and contribution activity
- Call out specific repos you've contributed to (especially well-known projects)
- Open source contributions are often stronger signals than personal projects

---

### Section 8 — Contact *(Required)*

Make it dead simple to reach you:
- Contact form, or
- Email · GitHub · LinkedIn plainly listed

Don't make someone hunt for your contact info.

## Do's and Don'ts

### ✓ Do

- Tailor every resume to the specific job description
- Use numbers and metrics in every bullet point
- Keep consistent date format throughout (e.g. Jan 2022, not 01/2022)
- Make your portfolio fully mobile-responsive
- Show your GitHub contribution graph — activity matters
- Include a README for every GitHub project
- Proofread for typos (use Grammarly or a peer reviewer)
- Keep your resume in an ATS-friendly single-column layout
- Make your portfolio load in under 2 seconds
- Get at least one peer review before submitting

### ✗ Don't

- Use a two-column layout (ATS parsers break on these)
- Add a photo, age, marital status, or nationality to your resume
- List skills you can't defend fluently in an interview
- Use an objective statement ("I am looking for a role where...")
- Use tables, text boxes, or headers/footers in Word/PDF
- Deploy a portfolio with broken links or 404 errors
- Use skill bars or star ratings
- List every technology you've ever briefly touched
- Show only tutorial projects (Todo app, Weather app)
- Use vague verbs: "worked on", "helped with", "involved in"

## ATS Optimisation

Most large companies use Applicant Tracking Systems to filter resumes before a human sees them.

| Factor | What to do |
|--------|-----------|
| Keywords | Copy exact phrases from the job description |
| File format | Always PDF (unless DOCX is explicitly requested) |
| Layout | Single column — no tables, no text boxes, no graphics |
| Fonts | Standard only: Calibri, Arial, Helvetica, Times |
| Section headers | Use standard names: "Work Experience" not "My Journey" |
| Dates | Consistent format — Month YYYY or MM/YYYY |
| Acronyms | Spell out and abbreviate: "Amazon Web Services (AWS)" |

## Strong Action Verbs

Use these to start every resume bullet. Past tense always.

### Built / Created
`Built` · `Developed` · `Designed` · `Architected` · `Engineered` · `Implemented` · `Launched` · `Created` · `Established`

### Improved / Optimised
`Optimised` · `Reduced` · `Increased` · `Improved` · `Accelerated` · `Streamlined` · `Automated` · `Eliminated` · `Scaled`

### Led / Managed
`Led` · `Mentored` · `Managed` · `Coordinated` · `Spearheaded` · `Drove` · `Owned` · `Facilitated` · `Championed`

### Shipped / Delivered
`Shipped` · `Deployed` · `Migrated` · `Integrated` · `Released` · `Refactored` · `Maintained` · `Delivered` · `Resolved`
